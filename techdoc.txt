# Avighnya Foods — Technical Architecture & Technology Description

## 1. Technology Architecture

The Avighnya Foods platform will be developed as a **centralized, modular business management application** designed to manage CRM, sales, purchasing, inventory, dispatch, billing, receivables, reporting, and multi-company operations.

The system will use a **modular monolithic architecture** initially. This provides the simplicity of a single application while keeping each business module logically separated so that individual services can be scaled or extracted later if required.

### High-Level Architecture

```text
                         USERS
                           │
              ┌────────────┴────────────┐
              │                         │
           Desktop                    Mobile
              │                         │
              └────────────┬────────────┘
                           │
                         HTTPS
                           │
                           ▼
                    ┌─────────────┐
                    │    NGINX    │
                    │ Reverse     │
                    │ Proxy       │
                    └──────┬──────┘
                           │
              ┌────────────┴────────────┐
              │                         │

        ┌─────────────┐          ┌─────────────┐
```

# 9. Multi-Company Database Architecture

The system will support **four business firms under one organization**.

The database will therefore use a company-level data isolation model.

Example:

```text
Organization
│
├── Company A
│   ├── Customers
│   ├── Products
│   ├── Inventory
│   └── Invoices
│
├── Company B
│
├── Company C
│
└── Company D
```

Major transactional tables will contain:

```text
organization_id
company_id
```

This allows the owner to:

* Switch between companies
* View individual company reports
* View consolidated reports
* Compare companies
* Control company-level access

The backend will always verify that the logged-in user has permission to access the selected company.

# 10. Database ORM

The backend can use **SQLAlchemy 2.x** as the ORM with **Alembic** for database migrations.

This allows developers to define database models such as:

```text
Customer
Product
Invoice
Payment
Warehouse
InventoryTransaction
```

while maintaining proper database relationships.

Alembic will manage schema changes between versions.

Example:

```text
Version 1
   ↓
Version 2
   ↓
Version 3
   ↓
Production
```

This is safer than manually modifying production tables.

For example:

```text
            │
```

# 13. Inventory Engine

Inventory will use a **transaction-based inventory ledger** instead of simply storing a manually editable stock number.

Example:

```text
Purchase       +500 KG
Sale           -100 KG
Adjustment      -10 KG
Transfer        -50 KG
Transfer        +50 KG
```

The system can determine:

```text
Available Stock
Reserved Stock
Total Stock
```

at any point.

### Batch Tracking

Since Avighnya Foods deals with food ingredients, batches will be tracked.

Each batch can contain:

```text
Batch Number
Product
Manufacturer
Manufacturing Date
Expiry Date
Purchase Cost
Warehouse
Quantity
```

This enables traceability from purchase through sale and dispatch.

# 16. Billing Engine

The billing module will calculate:

```text
Quantity × Unit Price
        ↓
Gross Amount
        ↓
Discount
        ↓
Taxable Amount
        ↓
GST
        ↓
Invoice Total
```

The invoice will store a **snapshot of the transaction**.

This means if a product's price changes later, previously generated invoices will not change.

---

# 17. Credit & Receivables Engine

The system will automatically calculate:

```text
Invoice Amount
        -
Payments Received
        =
Outstanding
```

It will then compare:

```text
Invoice Date
+
Credit Days
=
Due Date
```

The system can categorize invoices as:

```text
Not Due
Due Soon
Due Today
Overdue
Partially Paid
Fully Paid
```

The aging report can then provide:

```text
0–30 Days
31–60 Days
61–90 Days
90+ Days
```


Backups should cover:

* Database
* Uploaded documents
* Invoice files
* Configuration required for recovery

A restore procedure should also be tested periodically.

**A backup that has never been restored is not a fully trusted backup.**

### In simple terms

**Next.js** = what the users see.

**FastAPI** = the brain/business logic.

**PostgreSQL** = stores the business data.

**Redis** = fast temporary data + job queue.

**Worker** = handles heavy/automatic tasks.

**Nginx** = receives internet traffic and routes it safely.

**Docker** = packages and runs all components consistently.

**GitHub** = stores and manages the source code.

**GitHub Actions** = automatically tests and deploys the application.

**VPS** = where the production system runs.

This is a **solid, practical architecture for Avighnya Foods v1** without over-engineering it with Kubernetes, microservices, or expensive cloud infrastructure from day one.
